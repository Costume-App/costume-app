# Training Video 5 (House Inventory) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Script, record, build, and QC video 5, "House Inventory": finding the inventory, the photo tile grid (categories, search), adding an item with details and a photo, the item that video 4 logged and its "Made for" line, reusing an inventory item in a production ("+ add from inventory", the "On hand" source, the view-only peek), and the "Used in" line that results.

**Architecture:** Same recipe as video 4. Every prep runs `resetDemoCostumeOrg` (inventory cleanup by exact name, maker colors), then a new `resetDemoInventory` that recreates a fixed set of photographed items, then `resetTwelfthNight` from video 4's end state. `resetTwelfthNight` learns one new design shape, a design pulled from inventory by item name. The item photos are synthetic product shots generated by a repo script, like video 4's sketch. Nothing in this video calls AI.

**Tech Stack:** Node ESM scripts, Playwright 1.63, ffmpeg/ffprobe (no `drawtext`), edge-tts in `~/.venvs/edge-tts`, Vitest (`scripts/**/*.test.mjs` and `src/**/*.test.ts`), the app's API as the demo user.

**Spec:** `docs/superpowers/specs/2026-09-22-training-videos-design.md` (video list item 5). Also read `docs/training-videos/README.md`, `docs/training-videos/followups.md`, `docs/superpowers/plans/2026-09-26-training-video-4-costume-creations.md` (its Task 5 is the model for Task 5 here), `scripts/lib/walkthroughs/costume-creations.mjs`, and `~/.claude/skills/recording-app-training-videos/lessons.md` before any walkthrough work.

## Review Focus

1. **Inventory items in the demo org that no video created** (someone added one by hand, or an earlier plan's name list missed one). They would show on camera as unexplained tiles. Expected: before recording, a preflight lists every inventory item name not in `DEMO_INVENTORY_NAMES` and the recorder refuses to film while any exist, naming them; nothing is deleted automatically. Pinned by a Task 2 test (`assertDemoInventoryOnly`) and Task 5 Step 1.
2. **A seeded item whose name is not in `DEMO_INVENTORY_NAMES`.** Cleanup only deletes listed names, so it would pile up one copy per take. Expected: `resetDemoInventory` throws before any write. Pinned by a Task 2 test.
3. **Tiles filmed before their photos load.** The grid would show empty garment-icon tiles for a second. Expected: the walkthrough waits until every tile image in view has `complete && naturalWidth > 0` before the first beat of any grid section. Pinned by the `waitForTilePhotos` guard in Task 5 Step 2.
4. **An inline field typed on camera that never blurs**, so its auto-save never fires and the "Saved ✓" flash never shows. Expected: the add-item section blurs each field (Tab) and waits for `Saved ✓` before the next, then reads the item back through `GET /api/inventory` and throws if any typed value is missing. Pinned by Task 5 Step 2.
5. **A design pulled from an item that the prep has just recreated.** The item ids change on every take, so a design keyed by a stale id would 404. Expected: `resetTwelfthNight` resolves `fromInventory` by item name through the `inventoryIds` map returned by this take's `resetDemoInventory`, and throws on an unknown name before any write. Pinned by a Task 2 test.
